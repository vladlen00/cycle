## Архитектура CRUD

Запись и чтение данных в таблицу cycles идёт через отдельную Edge Function cycles-api (НЕ через прямой REST к /rest/v1/).

Поток:
- Frontend → POST /functions/v1/cycles-api с body { action, payload } и заголовком Authorization: Bearer <токен>
- Edge Function проверяет подпись токена своим JWT_SECRET и берёт user_id из поля sub
- Выполняет CRUD к cycles через service_role (обходит RLS), с явным фильтром по user_id из токена
- Возвращает результат

Подпись initData проверяет другая функция, verify-access, при выдаче токена. Сам cycles-api initData не видит.

Поддерживаемые actions: list, create, update, delete.

Колонка user_id в таблице cycles текстовая. В неё пишется Telegram user.id строкой, не случайный localStorage ID.

Anon key из Supabase в коде фронта НЕ используется (в отличие от biohack). Все запросы к данным идут только через cycles-api.

Edge Function verify-access остаётся отдельной и не трогается, она проверяет членство в платном канале и пускает в мини-аппу.

## Функционал (актуальный состав в HANDOVER.md)
1. Главный экран: круговой индикатор с днём цикла, фазой, прогнозом следующей менструации

4. История: последние 6 циклов с длительностью и отклонением от среднего
5. Редактирование записей

## Логика расчёта (вынести в cycleCalc.js)
- Лютеиновая фаза всегда ~14 дней
- День овуляции = средняя длина цикла - 14
- Менструация: дни 1..menstruation_length_days (по умолчанию 5)
- Фолликулярная: между концом менструации и днём овуляции
- Овуляция: окно из 3 дней вокруг расчётного дня
- Лютеиновая: после овуляции до следующей менструации

Типичная длина цикла = МЕДИАНА последних 6 валидных интервалов, фильтр аномалий 15-45 дней. Если валидных интервалов нет, функция возвращает null, и это НЕ повод подставить 28: выдуманное число женщина читает как своё. При null приложение показывает "Данных мало для прогноза", не рисует дугу кольца, не рисует прогнозные дни в календаре и в картинке, а в истории и превью дня честно говорит, что фаза неизвестна.

Нижняя граница 15, а не 21: цикл в 20 дней редкость, но он реален. Фильтр отсекает опечатки ввода, а не нездоровье. Подробности и обоснование обеих границ в комментарии над константами в `cycleCalc.js`.

## Палитра
Тёплая женская: пастельный розовый, кремовый, бежевый.
- Менструация: мягкий красный (не ярко)
- Фолликулярная: мятный
- Овуляция: золотистый
- Лютеиновая: лавандовый

ВАЖНО: не использовать длинные тире нигде, только короткие дефисы. На "ты". Тёплый, поддерживающий тон.

## Интеграция с трекером (сделана)
Фаза цикла уходит в ИИ-подружку из соседнего репозитория: ../biohack/src/cycleContext.js тянет циклы через cycles-api и считает фазу автономной копией логики.

Расхождение чисел ЗАКРЫТО 11.09.2026 парной правкой в обоих репозиториях: одинаковые границы 15-45, одинаковое окно в 6 интервалов, одинаковый limit 12 в запросе, медиана вместо средней с одинаковой формулой чётного случая. Проверено 3000 случайных наборов дат, расхождений 0.

Копия остаётся копией, общего файла нет: Цикл это статика на GitHub Pages без сборки, трекер собирается CRA, и один файл на двоих требует либо сборки здесь, либо чтения window из React-кода. Контракт синхронизации записан в шапке `cycleCalc.js`: три участка SHARED-CALC обязаны совпадать с трекером. Правка в одном репозитории без парной правки во втором это баг, даже если ничего не упало.
