# HANDOVER: мини-апп "Цикл"

**Обновлён:** 11 сентября 2026
**Статус:** в проде, работает с реальными подписчицами

Документ описывает фактическое состояние проекта. Правила для агента лежат отдельно, в `CLAUDE.md`, он грузится автоматически. Хронология правок в `git log`.

## 1. Что это и где живёт

Telegram Mini App для трекинга менструального цикла, часть Студии Ирены Пол. Аудитория примерно 600 женщин платного канала.

- Точка входа: `t.me/relax2000_bot/cycle`, слаг `cycle` зарегистрирован в @BotFather
- Вторая точка входа: карточка "Цикл" в хаб-аппе studio, соседний репозиторий
- Фронт: GitHub Pages, репозиторий `vladlen00/cycle`, ветка `main`, адрес `https://vladlen00.github.io/cycle/`
- Бэкенд: Supabase, проект `kjzxrpwqyyjcykwbqskn`, функция `cycles-api` и таблица `cycles`

**Деплой фронта:** коммит в `main`, GitHub Pages пересобирается за 1-3 минуты. После этого обязательно поднять `?v=` в адресе мини-аппа в @BotFather, иначе WebView Телеграма отдаст старую страницу из кэша.

**Версии файлов внутри страницы** живут в `index.html` и поднимаются при каждой правке соответствующего файла.

## 3. Что приложение умеет сегодня

**Экран "Сегодня".** Кольцо с номером дня цикла и названием фазы, подпись с прогнозом следующей менструации, кнопка "Отметить менструацию".

**Экран "Календарь".** Пятнадцать месяцев: два назад и двенадцать вперёд. Липкая легенда фаз сверху. Менструация рисуется кружком с числом, овуляция контурным сердцем, фолликулярная и лютеиновая точкой под числом. Прогнозные дни отличаются визуально от прожитых.

- **Тап по дню открывает превью:** дата с днём недели, фаза, номер дня цикла, для дней без данных честное "Нет данных". Только чтение. У дня с реальной отметкой есть кнопка "Изменить запись". Раньше тап открывал форму СОЗДАНИЯ с этой датой, и "Сохранить" читалось как "ОК": подписчица так завела случайную отметку, которая сдвинула ей весь прогноз. Создание записи живёт только на кнопке "+" и на главном экране.
- **Полоса "Поделиться датами цикла"** отдельной строкой над навигацией. Видна только на календаре и только когда есть хотя бы одна запись. Выбор периода 1, 3 или 6 месяцев, дальше приложение рисует картинку и открывает её на весь экран.
- **Плавающая кнопка "+"** создаёт запись. Пока видна полоса "Поделиться", кнопка поднята на её высоту.

**Экран "История".** Последние шесть циклов: дата старта, длительность, отклонение от средней и лента дней с цветами фаз.

**Тост отмены.** После успешного создания записи пять секунд висит тост "Отметка добавлена" с кнопкой "Отменить". Она удаляет только что созданную запись и перерисовывает экран.

**Картинка для отправки.** Рисуется в памяти и никуда не загружается. Геометрия одна на все периоды, масштаб подбирается так, чтобы длинная сторона не вышла за 1280 пикселей: до этого размера Telegram ужимает фото при обычной отправке. Иерархия намеренная: менструация это круг, заливка у прожитого дня с отметкой и контур у будущего прогнозного; овуляция это маленькая точка под числом; фолликулярная и лютеиновая не рисуются вовсе. Легенда из двух пунктов плюс строка про заливку и контур. Фазы берутся тем же вызовом `getCalendarPhases` и с теми же входами, что и экранный календарь, цвета читаются из тех же переменных CSS: картинка не может разойтись с приложением.

Отправка идёт через `navigator.share`, кнопка показывается только если браузер подтвердил поддержку файлов. Кнопки "Сохранить" нет сознательно: подтвердить работу скачивания внутри WebView нечем, а кнопка, которая молча не срабатывает, хуже её отсутствия. Телеграмовские методы отправки тут не годятся: `downloadFile` и `shareToStory` требуют адрес по https, `shareMessage` требует подготовленное ботом сообщение. Всё это упирается в хостинг файла и правку бэкенда.

## 4. Расчёт фаз

Всё в `cycleCalc.js`:

- Лютеиновая фаза 14 дней, день овуляции равен средней длине минус 14, окно овуляции три дня
- Менструация это дни с первого по `menstruation_length_days`, по умолчанию 5
- Средняя длина цикла: интервалы между соседними отметками, отсев значений вне 21-45 дней, среднее по последним шести валидным, дефолт 28
- `getCalendarPhases` сворачивает номер дня только для будущего и только для самого нового цикла. Закрытые циклы и уже прожитые дни считаются без свёртки: при задержке выходит лютеиновая, и это правда, а не начало нового цикла

**Верхней границы у календаря нет.** Расчёт красит весь переданный диапазон, а `renderCalendar` передаёт конец последнего из пятнадцати месяцев. Клемпинга нет ни в UI, ни в расчёте. В памяти Claude лежит файл `cycle_app_calendar_upper_bound` с планом такого клемпинга: это нереализованный замысел, а не описание кода.

## 5. Инфраструктура

**Таблица `cycles`:**

| Колонка | Тип | Заметка |
|---|---|---|
| `id` | uuid | первичный ключ |
| `user_id` | text | Telegram user.id строкой, совпадает с полем `sub` в токене |
| `start_date` | date | дата начала менструации |
| `menstruation_length_days` | int | по умолчанию 5 |
| `notes` | text | необязательно |
| `created_at` | timestamptz | |
| `deleted_at` | timestamptz | мягкое удаление, у живых строк null |

Ограничение `cycles_user_date_unique` на паре `(user_id, start_date)`. RLS включён, но `cycles-api` ходит под `service_role` и обходит его, поэтому защита сделана в коде: явный фильтр по идентификатору из токена в каждом запросе.

**Функция `cycles-api`.** Действия `list`, `create`, `update`, `delete`. Настройка `verify_jwt` выключена, иначе шлюз Supabase заблокирует наш токен раньше, чем код функции до него дойдёт.

- `list` отдаёт только живые строки, по убыванию даты
- `create` это upsert по паре пользователь и дата с обнулением `deleted_at`: повторное добавление удалённой даты реанимирует старую строку, дубликата не появляется
- `delete` мягкий, проставляет `deleted_at` и идемпотентен: повтор вернёт `deleted: false` и не перепишет метку времени

Разрешённые адреса: `app.irenabio.com`, `*.vercel.app`, `*.netlify.app`, `*.github.io`, `localhost`, `web.telegram.org`, `t.me`.

Деплой функции только через CLI с флагом, сохраняющим выключенный `verify_jwt`. Деплой через MCP сбрасывает эту настройку и ломает вход.

**Переменные окружения:** `JWT_SECRET`, общий с `verify-access`, любое расхождение даёт вечный 401; `SUPABASE_URL`; `SUPABASE_SERVICE_ROLE_KEY`.

## 6. Вход

**Дверь 1, Телеграм.** `initData` уходит в `verify-access`, оттуда приходит токен и ложится в `localStorage` под общим для всех мини-апп Ирены ключом.

**Дверь 2, веб.** Токен и срок жизни приходят в хэше адреса, забираются при старте и сразу вычищаются из истории, чтобы не утекли вместе со ссылкой. Дверь активна только там, где нет `initData`.

Ответ 401 от `cycles-api` чистит токен и показывает экран с предложением подписки: на вебе он ведёт в приложение, в Телеграме в бота.

## 7. Открытые хвосты

- **Разные диапазоны средней длины цикла.** Здесь интервалы фильтруются диапазоном 21-45 дней, а в соседнем репозитории, в `../biohack/src/cycleContext.js`, автономная копия того же расчёта для ИИ-подружки использует 18-45. На реальных данных подписчицы это дало 28 дней на экране и 24 у подружки: женщина видит два разных числа. Чинить в `biohack`, здесь трогать нечего, соседняя папка только для чтения.
- **Календарь и История расходятся в дне овуляции для закрытых циклов.** История считает фазы по фактической длине цикла, календарь по средней. Расхождение осознанное: сдвиг фертильного окна это продуктовое решение, а не хотфикс.
- **Главный экран при задержке пишет "Следующая ~" с датой в прошлом.** Прогноз это старт плюс средняя длина, без оглядки на сегодня.
- **Сетевой слой без страховки.** В `auth.js` один запрос без таймаута, повтора и запасного маршрута. Потерянный ответ даёт ложное "Не удалось удалить", хотя на сервере всё прошло. Данные не портятся: повтор идемпотентен.
- **Версию в @BotFather приходится поднимать руками** после каждого деплоя.

## 8. Правила работы в репозитории

- **Никаких длинных тире.** Нигде: код, комментарии, тексты интерфейса, надписи на картинке, сообщения коммитов. Только короткий дефис.
- **Соседние папки только для чтения.** Всё, что лежит рядом с `cycle`, это работающие мини-аппы с живыми подписчицами. Читать можно, писать, коммитить и запускать нельзя. Подробности в `CLAUDE.md`.
- **Маленькие шаги.** Сначала чтение и план в чате, правка только после явного "ок".
- **Никакого прямого обращения к базе из фронта.** Только через `cycles-api`. Публичный ключ Supabase в коде фронта не используется.
- **`_references/` не коммитится.**
- **Поднимать `?v=`** у изменённого файла в `index.html`, иначе правка не доедет до женщин.

## 9. Подводные камни

- Пришёл 401 на свежий токен: сверить `JWT_SECRET` у `cycles-api` и `verify-access`.
- Блокируются запросы с нового адреса: дополнить список разрешённых в `edge-functions/cycles-api/index.ts` и передеплоить функцию.
- Случайно включился `verify_jwt`: вход умирает целиком.
- Идентификатор Telegram привязан к аккаунту, а не к устройству: один аккаунт на телефоне и на десктопе это один и тот же пользователь.
- `height: 100svh` на контейнере означает, что прокручивается внутренняя область, а не страница. Навигация всегда на экране.
